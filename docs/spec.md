# Protoc Plugin Specification

> **Status:** Draft v0.1 — 31 Oct 2026
> **Owner:** Pascal Laenen

## 1. Purpose

A `protoc`/`buf` plugin, written in Go on `google.golang.org/protobuf/compiler/protogen`, that generates extra Go code next to the output of `protoc-gen-go`. It reads standard and custom proto annotations and emits code that is:

- **Transport-agnostic.** No gRPC or Connect dependency in the generated code unless a feature asks for one.
- **Free of runtime dependencies where possible.** Generated code uses only the stdlib and `google.golang.org/protobuf`.
- **Deterministic.** The same input always gives byte-identical output.
- **Feature-gated.** Each generator is switched on with a plugin parameter.

This spec covers: the shared architecture every feature follows, and the first extension: **typed resource names from `google/api/resource.proto`**.

## 2. Current state

None — greenfield; the only feature is `resname`, and `features=` defaults to `resname`.

## 3. Architecture

### 3.1 Repository layout

```
cmd/protoc-gen-resname/main.go     # entry point, parameter parsing only
internal/plugin/plugin.go          # feature registry + dispatch
internal/feature/<feature>/        # one package per generator
    generator.go                   # Generate(*protogen.Plugin, *protogen.File, Config) error
    model.go                       # intermediate model built from descriptors
    template.go                    # emission (g.P(...) or text/template)
internal/naming/                   # shared naming rules (snake→Camel, collisions)
internal/annotations/              # helpers to read extensions safely
testdata/
    proto/...                      # input protos per feature/scenario
    golden/...                     # expected generated output
```

### 3.2 Pipeline

CodeGeneratorRequest → protogen.Options{ParamFunc}.Run → for each file with Generate == true → for each enabled feature: 1. build model (read descriptors + annotations, validate); 2. if model empty → emit nothing (no empty files); 3. emit file `<basename>_<feature>.pb.go`.

Rules: Model first, then emit (feature code must not read descriptors while emitting; all validation happens while the model is built, so errors carry file, element and position). One output file per feature per input file. Imports go through `g.QualifiedGoIdent`. Generated-file header: `// Code generated by protoc-gen-resname <version>. DO NOT EDIT.` / `// source: <proto path>`.

### 3.3 Plugin parameters

Parsed in `main.go` through `protogen.Options.ParamFunc` and passed to features as a typed `Config`.

| Parameter | Default | Meaning |
|---|---|---|
| `features` | `resname` | List using `+`, e.g. `features=resname` |
| `resname_wildcards` | `true` | Allow `-` wildcard segments on parse |
| `resname_refs` | `true` | Generate typed accessors for `resource_reference` fields |
| `resname_ref_fields` | `names` | `names` (only `name`/`parent`/`*_name` fields) or `all` |
| `resname_strict_segments` | `false` | Segment charset `[a-z0-9-]{1,63}` instead of permissive |
| `strict` | `false` | Treat warnings (e.g. a missing `plural`) as errors |

`paths=source_relative` is honoured like protoc-gen-go. Output suffix `_resname.pb.go`.

Example `buf.gen.yaml`: protoc-gen-go with `paths=source_relative`, then `local: protoc-gen-resname`, `out: gen`, `opt: [paths=source_relative, features=resname]`.

### 3.4 Error handling

Invalid annotation (bad pattern, duplicate type) → error naming `file:message`, stop generation (`CodeGeneratorResponse.error`). Warning (style issue) → stderr; error with `strict=true`. Unknown parameter → error. Feature finds nothing to do → no file emitted, no error.

## 4. Extension: typed resource names (`resname`)

### 4.1 Goal

For every message annotated with `google.api.resource`, generate a Go type that parses, validates and formats its resource name, replacing hand-built `fmt.Sprintf`/`strings.Split`. Follows AIP-122 and AIP-123, close in spirit to einride's aip-go, but owned here and with **no runtime dependency**.

### 4.2 Inputs

`google.api.resource` (message) → the resource-name type(s); `google.api.resource_definition` (file) → types for resources without a message (external); `google.api.resource_reference.type` (field) → typed accessor returning that resource's name; `google.api.resource_reference.child_type` (field) → typed accessor returning the parent name (4.6). Go types from `google.golang.org/genproto/googleapis/api/annotations`.

### 4.3 Pattern grammar

```
pattern  := segment ("/" segment)*
segment  := literal | variable
literal  := [a-z][a-zA-Z0-9]*          # collection id, e.g. "books", "keyRings"
variable := "{" snake_name "}"         # e.g. "{book}", "{key_ring}"
```

Generation-time validation (each failure is an error): the pattern must alternate `literal/{variable}`; singleton patterns ending in a literal (`users/{user}/config`) are allowed and flagged as singletons; variable names unique within a pattern; the last variable should match `singular` else warning; `type` must be `{service}/{Kind}` with UpperCamel `Kind`, unique across the whole request (all files in the `CodeGeneratorRequest`, not only those being generated — like api-linter); `name_field` (default `name`) must exist on the message and be `string`.

### 4.4 Generated code: single pattern

Input: `message Book { option (google.api.resource) = { type: "library.example.com/Book" pattern: "publishers/{publisher}/books/{book}" singular: "book" plural: "books" }; string name = 1; }`

Output (`library_resname.pb.go`):

```go
const BookType = "library.example.com/Book"
const BookNamePattern = "publishers/{publisher}/books/{book}"
type BookName struct { Publisher string; Book string }
func ParseBookName(name string) (BookName, error)
func MustParseBookName(name string) BookName
func (n BookName) String() string                 // formats without validation
func (n BookName) MarshalString() (string, error) // validates, then formats
func (n *BookName) UnmarshalString(s string) error
func (n BookName) Validate() error                // all segments set, valid charset
func (n BookName) ValidateAllowWildcard() error
func (n BookName) ContainsWildcard() bool         // any segment == "-"
func (n BookName) Type() string                   // BookType
func (n BookName) Parent() PublisherName          // only if the prefix pattern is a known resource
func (n BookName) IsZero() bool
func (x *Book) ResourceName() (BookName, error)   // on the message, same package, separate file
func (x *Book) MustResourceName() BookName
```

Behaviour: segment charset permissive by default (non-empty, no `/`, `utf8.ValidString`), strict `[a-z0-9-]{1,63}` with the parameter; wildcard `-` accepted by Parse when `resname_wildcards=true`, rejected by `Validate` unless `ValidateAllowWildcard()`; errors wrap a per-package sentinel `ErrInvalidResourceName` with `%w` and context (`book name "x": expected 4 segments, got 1`); generated field names snake→UpperCamel via `internal/naming`, collisions with Go keywords/method names get `_` suffix + warning; `Parent()` only when the prefix pattern matches a resource known in this request (message or `resource_definition`).

Naming uses the short form: `BookName`, `ParseBookName`, `BookType`, `BookNamePattern` — not `BookResourceName`. No runtime package in v1: the sentinel `ErrInvalidResourceName` is emitted once per generated Go package.

### 4.5 Multiple patterns

Interface `BookName { String() string; Validate() error; Type() string; isBookName() }` + variant structs `PublisherBookName{Publisher, Book}`, `ShelfBookName{Shelf, Book}`; `ParseBookName` tries patterns in declaration order; variants named by joining the variables before the final one plus the Kind; the first pattern is canonical.

### 4.6 Resource references

`GetBookRequest.name [(resource_reference).type = "library.example.com/Book"]` → `func (x *GetBookRequest) BookName() (BookName, error)`. `ListBooksRequest.parent [(resource_reference).child_type = "library.example.com/Book"]` → `func (x *ListBooksRequest) ParentName() (PublisherName, error)`; with several possible parents the return type is an interface/variant (same mechanism as 4.5). A reference to a type unknown anywhere in the request (all files, generated or not) is an error. `type: "*"` generates no accessor. Repeated fields generate `…Names() ([]X, error)`.

**Which fields get accessors.** The owner's `contracts` repository annotates bare-UUID `_id` fields in `domain/` with `resource_reference.type` purely as type information (a deliberate AIP-124 deviation); resource *names* exist only in `api/`. Therefore accessors are generated only for `string` fields named `name` or `parent`, or whose name ends in `_name`; fields ending in `_id` (or any other name) get no accessor. The parameter `resname_ref_fields=all` generates an accessor for every `string` field carrying a `resource_reference`.

### 4.7 External resources (`resource_definition`)

File-level definitions generate the same types as 4.4/4.5 without the message accessor, in the Go package of the declaring file. Duplicate declarations: first by file order wins, others warn.

### 4.8 Out of scope for v1

`StreamID()` mapping for an event store, authorization object strings (OpenFGA/SpiceDB), field-mask/filter/pagination helpers, validation interceptors. Keep the model shaped so these can be separate features later.

## 5. Testing

Golden files: each `testdata/proto/<scenario>` compiled with `buf build -o image.binpb`; the test builds a `CodeGeneratorRequest` from the image, runs the plugin in-process, diffs against `testdata/golden/<scenario>/*.go`; `go test ./... -update` regenerates. Golden output is a real Go package built by `go vet ./...`. Table tests on generated types: round-trip `Parse(String(x)) == x`, wrong segment count, empty segments, wildcards, multi-pattern dispatch. Fuzz `FuzzParseBookName`: no panics, round-trip holds for accepted input. Negative scenarios with exact error messages. Determinism: run twice, byte-identical; map iteration always sorted.

Minimum scenarios: (1) single pattern top-level `publishers/{publisher}`; (2) nested with known parent Book→Publisher; (3) multi-pattern; (4) singleton `users/{user}/config`; (5) external `resource_definition` plus a reference to it; (6) `child_type` with one parent and with several; (7) a file with no annotations → no output; (8) invalid inputs, one scenario per validation rule in 4.3; plus (9) a `domain`-style file whose `_id` fields carry `resource_reference.type` → no accessors under the default `resname_ref_fields=names`, accessors under `all`.

## 6. Compatibility

Version printed in the generated header and via `--version` (ldflags, default `dev`). Generated API semver'd. Minimum Go version = module's `go` directive.

## 7. Acceptance criteria (resname v1)

All §5 scenarios pass with golden files committed; generated code depends only on stdlib + `google.golang.org/protobuf`; `go vet` and staticcheck clean on generated output; every §4.3 rule has a negative test with a stable error message; fuzz runs 60 s with no failures; README with the `buf.gen.yaml` snippet and one usage example.

## 8. Open questions (resolved)

1. Runtime package vs inline: **inline**, no runtime package in v1 — an `ErrInvalidResourceName` sentinel per generated package.
2. Segment charset: **permissive by default**; `resname_strict_segments=true` enables `[a-z0-9-]{1,63}`.
3. Type naming: **short form** `BookName`, `ParseBookName`, `BookType`, `BookNamePattern`.
4. Multi-pattern: **interface `BookName` + variant structs** `PublisherBookName`, `ShelfBookName`.
5. Message accessor: **`(x *Book) ResourceName() (BookName, error)` plus `MustResourceName()`**.
